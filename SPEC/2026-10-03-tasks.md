# Central de Tarefas

**Data:** 2026-10-03  
**Status:** Implementado  
**Plugin:** `plugins/operations/tasks`

## 1. Objetivo

Disponibilizar uma Central de Tarefas para organizar, distribuir e acompanhar trabalho operacional relacionado à eleição.

O módulo deve concentrar o ciclo de vida das tarefas sem introduzir dependência direta com outros plugins.

## 2. Escopo

O módulo contempla:

- dashboard;
- listagem de tarefas;
- visualização detalhada;
- criação e edição;
- Kanban;
- responsáveis;
- status;
- prioridade;
- comentários;
- dependências entre tarefas;
- dados de referência;
- navegação própria;
- integração com RBAC;
- auditoria e notificações através da infraestrutura da plataforma.

## 4. Dashboard

Deve existir visão resumida das tarefas operacionais.

Endpoint:

```http
GET /api/tasks/dashboard
```

A página deve apresentar dados derivados do backend e não métricas fictícias.

## 5. Listagem

Endpoint:

```http
GET /api/tasks
```

A interface deve permitir navegação para a tarefa correspondente e suportar os filtros previstos pelo contrato implementado.

## 6. Criação

Endpoint:

```http
POST /api/tasks
```

A criação deve utilizar DTO validado no backend.

A interface não deve reproduzir regras de negócio que pertençam ao service.

## 7. Detalhes e atualização

Endpoints:

```http
GET   /api/tasks/:id
PATCH /api/tasks/:id
```

A tela de detalhes deve centralizar as informações necessárias para acompanhamento da tarefa.

## 8. Kanban

O módulo deve fornecer uma visualização Kanban baseada no estado real das tarefas.

A movimentação ou alteração de estado deve persistir através da API.

O Kanban não deve manter um estado paralelo independente no frontend.

## 9. Comentários

Endpoint:

```http
POST /api/tasks/:id/comments
```

Comentários devem permanecer associados à tarefa e fazer parte do histórico operacional quando previsto pelo domínio.

## 10. Dependências

Uma tarefa pode depender de outra.

Endpoints:

```http
POST   /api/tasks/:id/dependencies
DELETE /api/tasks/:id/dependencies/:dependsOnId
```

A implementação deve impedir que o frontend precise manipular diretamente persistência ou relações Prisma.

As validações de dependência pertencem ao backend.

## 11. Dados de referência

Endpoint:

```http
GET /api/tasks/references
```

Dados externos necessários para formulários devem ser fornecidos através de contratos públicos.

## 12. Isolamento

É proibido importar implementação interna de outros plugins.

Exemplo proibido:

```text
tasks → shifts/src/**
tasks → field-teams/src/**
```

Integrações devem utilizar:

- API;
- contratos compartilhados;
- Event Bus;
- IDs persistidos.

## 13. RBAC

O plugin deve respeitar permissões de:

- leitura;
- criação;
- atualização;
- ações operacionais aplicáveis.

A autorização deve existir também no backend.

## 14. Event Bus, notificações e auditoria

Alterações relevantes podem gerar eventos, por exemplo:

- tarefa criada;
- responsável alterado;
- status alterado;
- comentário criado;
- dependência adicionada ou removida.

Consumers externos devem reagir através do Event Bus.

Não criar import direto de `tasks` para `notifications` ou `audit`.

## 15. Interface

O módulo dispõe de:

- dashboard;
- listagem;
- Kanban;
- criação;
- detalhes;
- cards e navegação próprios.

CSS específico permanece em:

```text
plugins/operations/tasks/src/client/styles
```

## 16. Critérios de aceite

A implementação é considerada válida quando:

- dashboard funciona;
- tarefas podem ser listadas;
- tarefa pode ser criada;
- detalhes podem ser consultados;
- alterações persistem;
- Kanban utiliza dados reais;
- comentários funcionam;
- dependências podem ser adicionadas e removidas;
- dados de referência são obtidos pela API;
- RBAC funciona;
- plugin permanece isolado;
- testes passam;
- typecheck passa;
- build passa;
- `check:boundaries` passa.

## 17. Fora de escopo

Não faz parte desta SPEC:

- transformar a home global em central de tarefas;
- criar dependência direta com Escalas;
- criar dependência direta com Checklist;
- mover regras do plugin para o shell;
- redesign global da plataforma.
